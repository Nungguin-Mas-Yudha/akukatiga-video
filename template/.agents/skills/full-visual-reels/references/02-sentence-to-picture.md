# Which event for which sentence

## Goal

For every beat, an event, not an illustration: an actor in a place, with something at stake, and what happens to it
on the trigger word. Written down as a plan the creator approves in words before any pixel exists.

## Reasoning

A viewer believes what they can see happen. "Your signup form has no age question" is a claim; a signup form filling
itself in, then a red dashed row opening where the age question should be, is evidence. The references never show a
chart, a stock icon or an abstract shape where a real artefact exists: they show the form, the judgment, the terminal,
the invoice, the profile. And they redraw it rather than record it, because only a drawn interface can turn red on a
word, grow a row, or become 108 copies of itself.

Fidelity goes to the maximum, scope to the minimum: real geometry, real copy (a correct `curl`, the real statute
number, the verbatim licence), and only the rows the sentence needs. A real screenshot is nine tenths irrelevant pixels
and one tenth illegible ones.

A real thing alone is still an illustration. The reference hook does not show a bomb; it drops a bomb toward an
island seen from the air (`workspace/projects/2026-10-29-full-visual-bom-hidrogen/reference-study.md`, Hook). The island is the place and the stakes, the
fall is the event, and the island comes back later to vanish. That is directing.

Start from the script, not from a look: for each sentence, name the actor, the place, the stakes and the event. A
sentence with no thing (a pure link, "it's a free skill called") gets nothing new: the stage keeps
living. Those are the weakest beats of any reel, so rewrite the sentence if you can.

## Every scene is an event

Each plan row names four things:

- **Actor:** the real thing the beat is about (the bomb, the extinguisher, the Chrome window, the agent).
- **Place:** a real setting it stands in: a table, a floor, a kitchen, an island, a street, a desk under a lamp. Never
  an object floating in an empty dark void. The ground stays dark (`taste.md`, Background); the place is drawn inside
  the dark ground, lit where the actor stands.
- **Stakes:** what can be lost or won, visible on screen (the island, the house, the money, the viewer's own form).
- **Event:** what happens on the trigger word: it falls, cracks, fills, turns red, is outnumbered.

An interface is its own place (the window, the page). A floating object with no place fails the plan gate.

## Three options before choosing

For each key beat, write three pictures before picking one:

1. **Literal:** the thing doing what the sentence says (the bomb falls).
2. **Point of view:** from inside the object, or through the actor's eye (inside the casing as the fuel is crushed;
   the island seen from the falling bomb).
3. **Scale or metaphor:** a contrast of sizes or a stand-in object (a tiny bomb over a huge island; one glass of water
   that becomes 1,700 glasses).

Pick the most surprising one that is still true. Write all three in `plan.md` for the hook, the mechanism and the
payoff at least, with the pick marked and one line on why. Built recipes for each option: `14-shot-recipes.md`.

## The table

The table gives the actor for common sentences. The plan still gives it a place, stakes and an event.

| The sentence... | The stage shows |
|---|---|
| names the viewer's own thing ("your signup form") | that interface, clean, filling itself in live |
| names a fault, or something missing | the same interface breaking in place. Absence cannot be drawn, its correction can: an inserted red dashed row with a `missing` pill, or a find bar typing the clause and returning `0 of 0` |
| states a price or a number | a counter that runs and lands on the word, at hero size when it is the payoff, with one grey line citing the source |
| multiplies ("per visitor", "5,000 were filed") | the single thing becoming a field of copies from its own position, while a counter runs |
| crosses a limit | a gauge or a bar filling, and flipping colour on the frame the value crosses, not on a word |
| names a repo or a tool | its GitHub card, the name typing on, the stars counting |
| describes a process between two parties | one artefact physically travelling between two identical panels; role badges and a round counter carry the state |
| says "turns X into Y" | X becoming Y on screen |
| claims a default, a setting, autonomy | a switch the cursor flips, and the consequence visible at once |
| cites authority | the real document, or a portrait with a name and a job title |
| lists stages in one sentence | columns or rows lighting in order, one per word |
| names the villain, or negates | one object alone in its place, struck through in the reel's only red stroke |
| turns the argument | a physical object (a stamp, a calendar rewinding) or the one layout move of the reel (two cards swapping, the thread object changing role) |
| gives the instruction | the action performed by a cursor in the real interface, then its consequence: the invoice zeroed, the switch flipped |
| closes the reel (the CTA) | a cursor in the real Instagram interface tapping like, share and follow; never a comment keyword or a promised file |

## Two habits above the table

**One continuous thing per reel.** An invoice that gains a line per item; the same nine objects flowing through five
layouts; two identical cards plus a terminal; one grid read four times (flags, then rates, then a scan, then marks).
It is the treatment's thread object (`12-treatment.md`). It is what makes six items one film instead of six slides,
and it doubles as a progress bar.

**A change of state never brings a new object.** The limit bar turns into the fallback bar turns into the token bar:
one rectangle, three states. Locks open, a gauge turns red, a row is inserted, a card desaturates. When something new
must arrive, the old thing is dimmed, shrunk and moved, overlaid, or morphed into it. Nothing is pushed sideways, and
the slot for a late arrival is left empty from the start.

## plan.md

Written after the approved treatment (`12-treatment.md`), which it follows. Once for the reel, at the top: the
concept, the thread, the HANDOFF table, the one big move and the chosen hook (from the treatment), the look line
(palette, finish, light), the pinned chrome, the one turn.

Then per scene, the sentence, and one row per beat (every key word, never more than 1.2 s apart):

| Column | Content |
|---|---|
| actor | the real thing, and the mockup it is copied from (`13-mockups.md`) or the new component's name |
| place | the setting it stands in, drawn inside the dark ground |
| stakes | what can be lost or won, as seen on screen |
| first frame | what is on screen at the scene's first frame: the HANDOFF it starts from, or the object mid-entrance |
| trigger word → event | `word → what changes`, marked "lands on" for a single event or "ends on" for a build |
| last frame | where the scene leaves its objects: the HANDOFF out |
| angle | the framing and shot size, from the vocabulary and shot grammar in `07-camera-and-transitions.md`; never the same as the previous scene |
| camera cause | the visible event that moves the camera (the slam, the copy leaving, the dive into the mark), or "locked" |

There is no transition column: the handover is the lift with HANDOFF, and a move between places happens inside the
scene. A rare `in:` transition is written as a note under its scene with its reason. Under the hook, mechanism and
payoff scenes, the three options (literal, point of view, scale or metaphor) with the pick marked. Every sentence gets a new picture:
a new shot, a new state, a new object or a new number. The source of each thing goes in Sources below. The creator
reads this in words and approves it, or not.

### Sources

One table, one row per drawn object: the object; what it is redrawn from (URL, document and page, product screen,
reference images, model); the type (screen, document, diagram, photo, model, script only); what was read off it
(ratios, part list, copy); parts marked `inference` when no reference shows them; the honesty label, if any. A
physical object with no reference row is not ready to be planned. The detail per object lives in
`reels/<slug>/references.md` (`object-references.md`).

### What good looks like

- Reading only the actor, place and event columns, someone could retell the story.
- Every beat has an actor in a place. Nothing floats in an empty void.
- The plant-and-payoff pairs from the treatment have their rows: where each is planted and on which word it pays off.
- Every machine, part, device or body part on the stage has a row in Sources pointing to a reference that was looked
  at as a picture, and its main proportions are written as numbers read off that reference.
- Every item uses the same skeleton, and the last item breaks it on purpose.
- The densest stage has at most five to seven things, each in a slot that was reserved for it.
- The payoff number is the only thing allowed to be bigger than the caption, and everything above it dims when it lands.
- People are portraits or drawn faces with a name, never initials or grey placeholders. Real logos only, fetched, never
  constructed.
- The first frame is the first word alone with the first object mid-entrance. The last frame reads on its own if paused.

### Traps

- An illustration instead of an event: the thing shown, centred, alone on the dark ground, with nothing at stake and
  nothing happening to it.
- The literal option taken by default. Write the point-of-view and scale options first; take the literal one only when
  it is the most surprising true picture.
- A stock-icon metaphor where an artefact exists (a shield for "security", a rocket for "launch"). A metaphor object
  is for a mechanism with no readable artefact (code, a server bug): a locker, a pass, a key ring, drawn with material
  and moving parts, inside the reel's one concept (`12-treatment.md`).
- A whole perfect interface where one row carries the sentence.
- A new card per sentence. Ask first what the thing already on screen can do: a new shot of it (the camera dives in),
  a new state, a new part. New does not mean replaced.
- One picture held for a whole scene. The first hydrogen-bomb plan gave each 13-17 s scene one object and measured a
  beat every 5 s; the bar is 1.2 s.
- Evidence set in type nobody can read: below 32 px it is texture. Fewer rows, bigger.
- A list with no structure mark: the viewer cannot tell how much is left. Give it the continuous thing, or the pill.
- Copying a claim from a reference reel into a plan. Verify it or drop it.
- Citing a manual whose figure nobody opened. Text pulled out of a PDF is not a reference image.
- A physical object drawn from memory because no screen exists for it. Fetch what it looks like first.
